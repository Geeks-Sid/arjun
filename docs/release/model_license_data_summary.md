# Model, license, and data summary

Research release baseline; not for clinical use.

## Models

Authoritative lists (generated + validated at release gate):

- `model_registry/v1_scope.yaml` — scope, capability, and accelerator support.
- `model_registry/licenses.yaml` — per-model license record (status, terms,
  gates).
- `docs/release/support_matrix.md` — model x task x backend status.
- `docs/recipes/*model_cards.md` — per-family model cards.

A model with `status: BLOCKED` or a non-approved license cannot load. Every
included model must have an approved license record and pinned revision before
it appears in a release note (checked by the license consistency validator in
`medfm/tools/release.py`).

## Licenses

- Schema: `model_registry/license_schema.json`; policy: `docs/licensing_policy.md`.
- Research-only models (CC-BY-NC-ND class) load only in research contexts;
  `accepted_terms_date` is recorded before any gated download.
- Commercial-safe and research-only classes are separated; the registry never
  guesses an unresolved term.

## Data and split integrity

- Dataset provenance lives in manifests (Phase 03) with `report_uri` references
  only; embedded report text is rejected.
- Split integrity: SHA-256 group hashes, leakage audits (Phase 03 + ADR-0004).
- Every dataset-derived result in a validation report records its manifest
  revision and preprocessing hash; the Phase 16 report schema enforces this.

## Checksums

`docs/release/checksums.txt` (regenerated by
`python -m medfm.cli.release checksums`) pins SHA-256 for release docs and
artifacts.
