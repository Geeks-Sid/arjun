# Compatibility matrix (release)

Research release baseline; not for clinical use. Exact tested topology/runtime
for protected jobs is recorded in the protected-hardware run reports and the
registry smoke records, not inferred.

## Model x task x backend

`docs/release/support_matrix.md` (generated by
`python -m medfm.cli.release matrix`) is the authoritative model x task x
backend status table. Statuses are: supported (with smoke revision/date),
blocked (with reason), or explicitly untested (`UNTESTED` /
`CPU_CONTRACT_ONLY` / `NOT_APPLICABLE`).

## Deployment / inference

`docs/inference/deployment_matrix.md` is the authoritative runtime policy:

| Backend | Load | Inference | Evidence required |
| --- | --- | --- | --- |
| CPU | safetensors, FP32 | bundles declaring `tested` | bundle load, output parity, memory cap |
| CUDA | CPU safetensors + placement | FP32/BF16/FP16 when declared | latency, peak VRAM, parity |
| TPU/XLA | CPU safetensors + XLA placement | fixed static buckets only | bucket warmup, compile count, sync |

## Quantization guidance

- CUDA: QLoRA via bitsandbytes NF4 (`docs/release/cuda_qlora_vs_tpu_bf16_lora.md`).
- TPU: BF16 LoRA only; NF4 is enforced off at the config gate
  (`medfm release validate` time in `medfm/tools/release.py::no_tpu_nf4` and at
  runtime by `medfm.peft.quantization`).

## Test topology and runtime pins

PyTorch 2.9.0, torchvision 0.24.0, MONAI ≥ 1.5, transformers/peft/accelerate
per `uv.lock`; TPU via `torch_xla[tpu]==2.9.0`. Any runtime pin change requires
re-running the protected jobs and updating this document and the registry smoke
records.
