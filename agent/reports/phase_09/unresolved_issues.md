# Phase 09 unresolved issues

1. **TPU runtime unavailable.** `torch_xla` is not installed on this workstation, so TPU HBM, XLA compile counts, host synchronization, CUDA/TPU parity, and adapter reload after XLA placement were not executed. The implementation keeps static `(32, 64, 128)` visual buckets, `(256, 512, 1024)` text buckets, SDPA/eager/XLA-compatible paths, tied-weight retie, and an explicit zero-steady-state-recompilation gate. The Phase 09 acceptance criterion permits this explicit block.
2. **Real upstream checkpoints remain gated.** MedGemma's native wrapper verifies an official connector when a real model is supplied; M3D-LaMed requires explicit license/research acknowledgements. Tests use offline tiny local models and do not claim upstream checkpoint compatibility or clinical performance.
3. **Repository-wide test invocation is environment-blocked.** `PYTHONPATH=. pytest -q` could not collect the entire pre-existing suite because `safetensors` is absent and several existing phases reuse identical bare test module names. The required isolated Phase 09 command passes.
4. **CUDA measurements are tiny-reference measurements.** The reported VRAM values are for a hidden-256/depth-2 local LM and short text, not a 4B production checkpoint. Production memory must be remeasured after the Phase 10/12 recipes select concrete weights, precision, and batch sizes.
